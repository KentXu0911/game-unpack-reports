特殊块生成位置与激活时机

玩家交换出的道具，生成在交换端点

交换判定保存匹配组时，把组的生成格直接写成对应端点：被拖动的棋子换到哪格、所在组就在哪格生成；被换走的那颗如果也成组，就在另一端生成。消除阶段读取生成格时发现已有值，直接返回，不洗牌也不比较。［B2、B10］

GetSpecialItemCell(group):
    if group.creationCell != null: return group.creationCell   // 交换组
    SelectItemCreationCell(group)
    return group.creationCell

SelectItemCreationCell(group):
    ShuffleCells(group)        // 洗栈上副本：只消耗难度随机数
    bestTime = 0
    for cell in group.cells:   // 原顺序
        if cell或当前棋子缺失: 报错
        t = 当前棋子的状态改变时间
        if cell有Chain: continue
        if t > bestTime or best == null or cell.Y > best.Y:
            best = cell; bestTime = t
    group.creationCell = best

连锁出的道具，倾向最新落下或更高的格子

自动消除的组没有端点，才走比较：按组内原顺序逐格看，跳过锁链格（StaticItemType 6），新格的状态改变时间更晚，或位置更高（Y更大），就替换当前选择，所以结果与遍历顺序有关。状态改变时间这一字段按复刻工程的接口解析确认。

洗牌函数把组的14格数组复制到栈上再打乱，不写回，不影响选格，只消耗一次难度随机数。收集数据和特殊块数据两处各拿一份组副本、各调用一次，普通三消也会走到；按随机数复刻时这两次消耗都要计入。

生成格留下，其余匹配格清掉

选定位置后，这一格会从普通销毁和收集列表中排除，其余匹配格继续进入清除流程，特殊块就在这一格出现。

等创建阶段结束，再恢复落子

创建延迟是0.17秒：MatchItemView的静态构造读入0.2与0.85两个常量，SpecialItemCreator的静态构造相乘一次后固定。等待按关卡时钟逐帧累加。延迟到达后依次显示画面、设置排序、启用模型并播放出现动画，再等一帧，检查覆盖物、绑定粒子，最后解冻匹配组。解冻时刻是“延迟＋一帧”，不跟随出现动画的总长。［B10］

位置和时机会改变组合机会

特殊块留在哪格，决定下一手能否接上其他道具；何时激活、何时恢复下落，决定连锁节奏。复现时要把生成位置、显示、可操作和恢复下落分别对齐。

命中去重、扩散与连锁节奏

同一轮爆炸只登记一次命中

每轮爆炸都有自己的编号。物体收到伤害时，先查这个编号是否已处理：处理过就退出，没处理过就登记，再尝试受击。这样，同一轮爆炸从多个入口碰到同一物体时，不会反复扣层；不同编号的爆炸在同一帧仍可各扣一次。多格物体与全层清除的路径另有分支。［B11］

蘑菇扩散要等操作条件满足

蘑菇不会只看棋盘上有没有空位。扩散前会检查是否允许扩散、是否还有待处理操作，以及特定操作是否存在。若上一手销毁了蘑菇或土壤，已检查的流程会清理并退出；满足条件、有土壤和候选格后，才继续分组、排序和随机选格。候选排序的比较器尚未全部还原。［B11］

移动中的格子也会影响扩散

候选格必须是允许使用的普通格，还要避开阻挡触摸的物体和预留格。程序同时检查土壤、棋子当前位置、下一位置、下落目标以及冻结状态。看起来空着的格子，可能已经被正在下落的棋子占用。

伤害、下落和特效有各自的时刻

自动引爆、下落、胜负判断和洗牌按管理器注册顺序执行，运行时还可能插入或替换步骤。已确认的时长常量都属于各自分支：

连锁的力度与节奏由这些规则共同决定

一次爆炸扣几层、蘑菇是否等落子结束再长出、下一轮引爆什么时候接上，都会改变玩家看到的连锁结果。复现时既要对齐伤害和棋盘状态，也要对齐特效与回调。
