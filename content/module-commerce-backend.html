拆包事实：商品、支付与实验接口

事实层

字段来自协议命名空间的结构声明。请求是客户端发出的内容，响应是客户端会读取的内容。

分析提炼：服务端掌握哪些决定

分析层

结论由字段组合读出；标“推断”的是对用途的解释。

收据由服务端校验，重复收据会被拦下。购买校验请求带 ProductId、TransactionId、Receipt 和 Platform；结果分 Verified、UsedBefore、Fail、VerificationNotCompleted 四种，响应还标出 IsSandbox 与 PurchaseTime。UsedBefore 说明同一笔交易的二次提交会被识别；校验怎么做、风控规则是什么，不在包内。
购买时会上报当前库存。购买校验请求带 CurrentUserInventory。
推断：服务端借此核对到账前后的资源；具体用途要看服务端。
支持 7 个支付平台。iOS、Android、Editor、Huawei、Samsung、Amazon、Xsolla。Xsolla 另有取令牌与取订单号两个请求，订单号只返回成功或失败。
实验分组由服务端分配。AssignCampaignAB 只发一个 Campaign 字符串，返回 NewAbData。客户端拿到组值后怎样读，见A/B测试；谁进哪组、各组比例多少，客户端看不到。
客户端把自己的礼包档位和实验组报给服务端。Journey Offer 查询请求带 Segment 与 AbGroup，返回整份 JourneyOfferInfo；Golden Offers 查询不带参数，直接返回 GoldenOffersInfo。两者的礼包内容都由服务端返回，所以离线包给不出某账号当期的礼包。
累计付费存在服务端。GetAllTimePurchase 不带参数，返回 PurchaseAmount 与 LastPurchaseTime。这是客户端能读到的唯一累计付费数字；单位（金额还是次数）要看消费代码。
兑换码与维护期购买也走服务端。远程奖励按 Code 查询和领取，失败原因有 Expired 与 AlreadyClaimed；维护期购买请求带一组商品 ID。
