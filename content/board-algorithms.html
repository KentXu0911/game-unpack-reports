一个格子不只记录“现在有什么”

画面上的位置与程序预订的位置可能不同。下落规划至少要区分三个登记：Current是棋子当前所属格，Next是下一段移动要进入的格，Target是规划时分配的目标关系。格子和棋子两端都保存这三种关系，所以移动中的棋盘要按登记表示，一张颜色数组不够。

例如，A正从上方落向空格C，B也在附近。画面上C还没被A占满，但A已经登记目标，后续规划会把C视为已预订，B不能领取。清理旧目标时，已被Next预订的关系保留。［B1］

已经看见三连，为什么有时要等一下才消除

“识别出形状”和“此刻可以自动引爆”是两次判断。匹配组要求每格棋子都准备好：没有正在交换、下落状态稳定、预留计数小于1。然后每列取组内最高的一颗，再检查上方的Target里有没有同色棋子正在加入。［B4］

在“上方Target是同色、但上方棋子还在下落”的分支中，程序比较当前关卡时间与下方这颗棋子的状态改变时间＋0.25秒。正常有限时间值下，当前时间不晚于这个阈值就继续等待；0.25秒只属于这个分支。上方棋子已稳定时：上方没有组就继续向上检查，有组则跟随上方组的准备结果。

例子：下方匹配组最高棋子的状态在关卡时间10.00秒改变，上方又有同色棋正落入。按关卡时钟，该分支在10.20秒、10.25秒仍要求等待；到10.26秒这条时间条件解除，其他准备条件仍要通过。

扫描本身也有门槛。AutoExplodeManager.ManualUpdate在洗牌（操作6）进行时不扫描；其他操作进行中照常扫描。没有任何进行中操作时，记录当时帧号，此后帧差大于10就停止扫描，直到再有操作发生。［B5］

【体验解读】这类等待给正在加入的同色棋保留合并机会，可能让玩家看到一次更完整的组合，也解释了“颜色已经连上，为什么没有立刻炸”。体感延迟还叠加动画与格子冻结。

GetNextItemOfCell读取的是Next而非Current：询问棋子是否允许落向目的格，并要求棋子没有另一个目标，或其Target仍是原来源格。落点自身的Next登记在冻结检查之前处理，所以被冻结的落点仍会接住已经预订进来的棋子。

例子：两颗棋子正在接连下落时，下一段落点可能已经预订。按Current颜色数组从上往下搬运，会漏掉这些在途关系，导致棋子重叠、跳格或同一颗被多个空格领取。原代码先规划登记，再由运动组件推进，这两步需要分开还原。

斜落：先检查落点，再检查通路和来源棋子

斜落就是上方的棋子从侧面滑进空位。程序先规划直落，再处理需要斜落的格子。一次斜落要依次通过落点资格、向上搜索、对角来源、左右选择四层检查。［B7］

1. 这个空位是否需要斜落

CalculateCrossFalls只处理普通格，而且必须已被标记为需要寻找斜落来源、没有Target、也不属于下层棋盘。Target表示已经分配的下落目标关系：即使画面还是空的，只要直落规划已把A分给这个位置，就不再让B斜着抢进来。

“需要寻找斜落”的标记由直落搜索在通路被挡时设置，并先经过ShouldFindCross：多棋盘关里当前棋盘的CanCrossFall为假，就直接不允许斜落；关内有冰块且上方有冰块时，还要检查斜落冻结计数和冰块下方邻格。［B7］

伪代码：斜落落点资格6行
for destination in 待处理格子:
    if not destination.IsNormalCell(): continue
    if not destination.shouldFindCross: continue
    if destination.Target != null: continue
    if destination.IsInBelowBoards(): continue
    FindCrossItem(destination)

2. 沿上方建立左右待检查位置，遇到阻断就停

FindCrossItem从落点开始逐格向上走。每到一个位置，依次检查：是否冻结、能否通行、是否被多个可下落物体瞄准、boardId是否仍与落点相同。任意一项失败，就停止继续向上收集。能否通行由当前物体的IsAvailableForFall决定，与这格有没有棋子是两回事。

在非空白格，程序分别检查紧邻的左格和右格。某侧邻格被冻结，就停止收集这一侧；另一侧仍可继续。其余情况下把当前访问位置压入对应栈，后面再取它的左上或右上来源验证。栈里保存的是待查位置，是否有可用棋子到弹出时再验证；左右两侧都停止后，向上搜索也结束。

FindTargetItemFromCrossCell先检查落点缓存的下方关联格。如果它存在、非空白且没有下落阻挡，就读取该格Target棋子的NextCell和CurrentCell：至少有一个存在，且Y小于本次访问位置的Y，才继续探对角来源；否则本次候选失败。下方关联格不存在、为空白或有阻挡时，跳过这一项检查。

4. 合法候选之间怎样选左边或右边

通过资格检查之后，才进入左右挑选。左栈弹出的来源若是合法普通棋，立即选它；若是合法特殊道具，则还会检查右栈，合法的右侧候选可以替换它。右侧失败时，左侧特殊道具仍可使用。两边都没找到就继续弹栈，找到后先登记Target，实际移动由后续更新推进。

伪代码：斜落左右选择10行

    chosen = 验证左栈弹出的对角来源（栈空则为null）
    if chosen存在 and not chosen.IsSpecialItem():
        SetTargetItem(destination, chosen)
        return
    right = 验证右栈弹出的对角来源（栈空则为null）
    if right存在: chosen = right
    if chosen存在:
        SetTargetItem(destination, chosen)
        return

构造例子：左边是合法红棋、右边是合法蓝棋，这轮直接选左边；左边是合法火箭、右边是合法蓝棋，这轮选右边；左边是合法火箭、右边无合法候选，则仍选火箭。这段选择没有左右各50%的随机，也没有按剩余关卡任务评分。

冻结：格子暂时不参与新的下落规划

这里的冻结是程序暂时占住格子的下落资格。例如交换已找到一组可以消除的棋，但交换表现还没结束，就先保护相关格子；下落搜索遇到冻结检查时，不能继续按普通格处理它们。这样可以避免已经认定的匹配被另一颗落子提前改写。这是运行状态，与冰块障碍无关。［B8］

冻结次数大于0，就仍有人占用

同一个格子可能同时被多个操作占用，所以FreezeFall用计数而非开关：冻结一次加1，释放一次减1；IsFallFrozen只问计数是否大于0。两次冻结需要两次释放，先结束的操作只能撤回自己那一次。

伪代码：格子冻结计数12行

    freezeCount += 1
    OperationStart(1)

UnFreezeFall():
    freezeCount -= 1
    OperationFinish(1)
    if freezeCount < 0:
        记录错误

IsFallFrozen():
    return freezeCount > 0

操作A冻结这个格子1仍冻结
操作B也冻结同一格2仍冻结

B结束，再释放一次0通过此项检查，继续检查其他下落条件

释放冻结不等于立即移动

计数回到0，只表示这一项限制已解除，下落还要通过阻挡、来源、Target和Next预订等条件。多释放一次会变成负数：记录错误，但不把负数改回0。

斜落另有一个独立的有符号计数，加减时不登记进行中操作。竖向火箭飞行时冻结整列和起点格，飞行结束再逐格释放；这个计数只在上文ShouldFindCross的冰块分支里被读取。

多棋盘：同一关内，从一段棋盘切到另一段

多棋盘是一关里有多段棋盘，当前只操作其中一段，流程推进时视图转到另一段继续玩。例如可以把它想成一张分段展示的长棋盘：前一段结束后画面移到下一段，仍在同一关里。程序用boards[]保存各段，用CurrentBoardId记录当前段；所以下落搜索必须检查boardId，只按画面上的上下左右取棋会跨段取错。［B9］

进入切换流程后，先锁输入，再移动棋盘

StartChangingBoard把IsChanging设为true，登记编号13的进行中操作，并禁用触摸。随后计算过渡时长，在时间0安排移动回调、在结束时间安排收尾回调，同时启动完成等待协程。起始回调用DOMove把棋盘移向传入的新位置，并使用传入的动画曲线；背景也有对应的滚动分支。

伪代码：多棋盘切换启动15行
StartChangingBoard(newPosition, boardCurve, backgroundCurve, speed):
    IsChanging = true
    OperationStart(13)
    heightDiff = CalculateHeightDiffBetweenBoards()
    DisableTouch()
    duration = 0.3 + sqrt(heightDiff) * 0.32 * speed

    在时间0执行: 按boardCurve移动棋盘到newPosition
    在时间duration执行: 切换动画收尾回调
    启动WaitForCompletion(isWater=false)

// 当前段编号的推进另在ChangeBoard中处理
ChangeBoard():
    if CurrentBoardId != 0:
        CurrentBoardId -= 1

boardId是段的内部编号，减1即转到下一段。ChangeBoard与画面移动是两个方法：复现时既要改编号，也要处理输入锁定与在途落子。

画面移动结束，与切换状态结束，是两个时点

结束回调先检查当前棋盘是否还有正在进入的物体；没有时调用AllowRefillOnNewBoard，允许新棋盘补入。随后结束编号13的操作、重新启用触摸，并通知切换完成事件。另一个协程持续检查HasAnyOperation：只有没有任何进行中操作时，才调用CompleteChangingBoard清除IsChanging，并恢复对应的镜头方向控制。

构造例子：棋盘移动到位时，如果另一个操作仍未结束，收尾回调已经可以重新启用触摸，但IsChanging仍会保持true，直到等待协程看到所有操作结束。能否接受某次交换另有其他输入门槛；IsChanging由“所有操作结束”清除，不按固定秒数。

移动时长与切换入口

公式是0.3＋√heightDiff×0.32×speed。例如给定heightDiff=9、speed=1，得到1.26秒；heightDiff=16时为1.58秒（计算例子，speed为调用方传入）。
