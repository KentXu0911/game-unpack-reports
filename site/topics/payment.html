拆包事实：商品标识、支付平台与校验结果

事实层

商品标识从 PurchaseHelper.get_*ProductId 的字符串常量反查得到；价位提示是标识尾号（如 pass.10 的 10），不是商店成交价。

分析提炼

分析层
远征活动是商品最多的一类。energyoffer 9 个、energysingle 8 个、energysingle3 1 个、energypass 2 个，合计 20 个，占 49 个固定标识的四成。依据：IAP 商品标识按前缀归并其次是 progressoffer（Journey Offer）的 6 档。这份列表里没有金币商店档位，金币礼包走另一套配置。
付没付过费，看到的是不同商品。Ego Offer 有付费用户版 egooffer.7 和未付费用户版 egooffer.1；极难关礼包有 extremelyhardleveloffer.3 和 .1 两版。依据：IAP 商品标识按前缀归并客户端按付费身份选商品标识，选取逻辑见分层与购买反馈。
价位提示覆盖 1–100 美元，共 18 档。同一前缀内可有多档，如 Journey Offer 的 1／5／15／25／50／100、远征单品的 6／10／20／25／30／40／50／100。依据：IAP 商品标识按前缀归并这些档位是商品的身份，实际金额由各地商店返回。
支付与到账。真钱商品进入 Native 或 Xsolla 路径，客户端把收据交服务端校验，结果是 Verified、UsedBefore、Fail、VerificationNotCompleted 之一，通过后更新奖励、活动进度及相关购买状态。依据：购买校验状态码枚举（PurchaseVerificationStatusCode）Xsolla 还受 A/B、国家白名单、后台禁用和凭证／初始化状态控制。金币商品用游戏内金币支付，不是商店货币报价。
广告与 No Ads。广告资格、冷却、场景和实验分别控制入口。No Ads 对插屏、失败续关广告与生命／金币激励广告的作用不同；此 build 的 TryAddNoAdsAutoDialog 返回 false，资源存在不等于会自动弹出。No Ads 有单买（noads.8）和捆绑（noadsbundle.12）两个标识。依据：IAP 商品标识按前缀归并

当前实价与广告需要单独采样

包内可以对上SKU、购买回调、价文显示与广告请求，但SKU后缀、numberId和金币奖励量都不是当地货币价格。金额、币种和价文应取对应地区的商店查询结果。

广告素材、填充与竞价结果来自广告服务；SDK和入口只说明客户端具备这条路径。实机记录可以证明当次看到了什么、是否发奖，不能单凭一次广告反推平台的竞价算法。

09 / PAYMENT

Native 和 Xsolla 两条支付路，外部支付还单独加赠

01

用户点购买

先过家长控制与购买中状态检查。

02

判断 Xsolla 可用

A/B、国家白名单、后端禁用、JWT/初始化状态。

03

选支付店

PaymentStore.Native 或 PaymentStore.Xsolla。

04

付款与验证

Native IAP 或 Xsolla web store，后续走核销/恢复与事件 claim。

05

奖励与历史

奖励包到背包；非 Pass 商品可更新付费身份和历史最高档。

官方外部店域名为 https://store.royalmatch.com，Xsolla Project ID 为 299375。PurchaseManager.StartPurchase 的 ARM64 方法体确实分支到 Native Library 或 XsollaPurchaseManager.StartPurchase，因此不是没用的 SDK 残留。

首购加赠

V2 首购组且奖励尚未使用时，返回 firstPaymentCoinBonus。首购通知门槛为玩家等级大于 51，即从 L52 起。

普通加赠

V2 默认组返回 lessCoinBonus；V1 少加赠组也返回 less；其他可用外部支付组返回 moreCoinBonus。

还不能给出的数字：lessCoinBonus / moreCoinBonus / firstPaymentCoinBonus 是每个 ShopPackageConfig 的配置值，本次还没有从真实商店响应拿到所有在售商品的当日数值。

人工／实机能做到什么，解包增加什么

人工／实机：能直接记录地区售价、实际广告，并验证购买、观看和到账。

解包增量：取得SKU、价文来源、支付回调、广告门控与奖励状态，帮助定位差异；实时金额、填充、后台核销和到账仍需运行验证。
