道具寻优：目标选择与通关收益

已取得哪些道具决策算法

普通飞机的选点与重选、组合飞机的行列／范围比较，以及智能火箭的横竖评分选择，都已有具体方法和分支依据。下面保留伪代码、箱子与拳击手套的数值例子，以及可修改输入的火箭方向演示。

算法决定当前攻击选择

这些规则根据当前棋盘、剩余任务与在途攻击挑选目标；部分组合还检查这次能否完成目标。它们能用于复刻已确认的道具决策，但尚未证明会让整关用最少步数通关。

飞机选点：评分、随机与目标重选

过滤与评分→高分组内抽取→剩余命中与重定向→登记攻击、飞行与命中

普通飞机怎样选中一个障碍

普通飞机采用先按规则评分，再从当前最高的可用评分组里随机挑选的方式。不同分数的障碍并非机会相同；同分的障碍也没有统一采用“最近的”“层数最少的”或“离完成任务最近的”来决定。落点还会受到已经飞来的攻击、障碍状态和重定向规则影响。［P1、P2］

  1. 遍历可参与选点的格子。非普通棋盘格，以及被阻挡飞机的覆盖物挡住的格子，不进入这一轮评分候选。这里检查的是格子的覆盖状态，不只是画面上看到的那一个物体。
  2. 计算攻击这个格子的价值。格子会交给上层覆盖物、格内物体或底层物体的相应评分规则处理。物体种类、当前状态和攻击类型会改变结果；一些收集到底部的目标还会带来额外分。分数用于选点，不是玩家积分或金币。
  3. 把相同分数放到同一组。程序把评分取负后存入有序字典，按键从小到大遍历，相当于先看高分组。另有特殊障碍的候选过滤，不能把所有屏幕上的障碍都当成已入组。
  4. 在当前组内抽取一个格子。使用本局随机数产生列表下标。如果抽到攻击的出发格、且组内还有其他格，会改取另一个列表位置。因此，“同分时有随机”已经有代码依据，但不能把任何局面都写成严格等概率。
  5. 检查这个格子还需不需要命中。还需要的命中数小于等于0，就移出这一组、继续挑；等于1时，这次可以选它，但会先把它从当前候选列表移除；大于1则保留。当前组没有可用格后，再看下一组。
  6. 处理重定向，登记在途攻击。候选格可能把攻击交给另一个有效目标。选定后会登记一发即将到来的攻击，供后续飞机判断；飞行过程中还有目标有效性检查。

过滤格子→按当前状态评分→高分组优先→组内随机、检查剩余命中→重定向与登记攻击

这是普通飞机首次选点的主要路径。已有目标的重选还有保留原目标的分支；飞机与火箭、TNT组合时，会先进入不同的范围选择流程。

适用条件：上表解释物体自身的评分分支。要直接拿来比较落点，应让这些物体都是有效候选，且没有其他覆盖层、底层目标、底部收集加分、原木／钻头等阻挡修正或重定向。格子最终分数不一定等于物体基础分。

分数有明显的优先档。客户端声明的五个基础档为1、26、676、17,576、456,976；物体也可以返回其他修正分数。它们表示程序赋予攻击的优先级，不能解释成“这个目标能带来456,976点任务进度”或“通关概率更高多少”。

四个具体局面，分别看它会怎么选

以下是按已确认代码构造的简化例子，用于解释分支，不是某一关的实机落点记录。除特别说明外，只比较列出的有效候选，不加入其他层或额外评分。

例1：左边箱子只剩1层，右边箱子还剩3层

两者都是456,976分。若它们处于当前最高可用组，且都不是出发格，程序会在这个同分组中随机挑选。左边一下就能打掉，并不会让它在这个箱子评分规则中自动胜出。

玩家若希望飞机先清掉左边，可能会觉得打右边“选错了”。代码能解释这个现象：这两格在当前评分里相同，算法没有在这一步继续比较哪一个更接近被清除。这也说明“飞机总优先打残血障碍”不成立。

例2：一个普通箱子，对比只差一下的拳击手套

箱子456,976分，拳击手套609,301分。如果拳击手套通过候选和剩余命中检查，会先在更高分组被考虑。它存在明确的收尾倾向；但这来自拳击手套的专用规则，不能推广成所有障碍都按剩余层数排序。

例3：两架飞机先后瞄准同一个箱子

普通箱子继承的剩余命中计算是当前层数 − 已登记的在途攻击数。1层箱子已经登记1发时，后续读取结果为0，在单格挑选分支中会被跳过；3层箱子登记1发后还剩2，仍有可能被下一架选中。［P4］

所以，两架飞机飞向同一个多层目标可能是有效的连续攻击，不能仅凭轨迹重复就说浪费。反过来，登记机制也不等于所有特殊障碍和组合都绝对不会打重；它们有各自的命中与重定向规则。

例4：一个箱子堵着通道，另一个箱子在开阔区域

假设两格在已计算的分数和候选条件上相同，当前单格选择就仍然在同分组中随机。它不会在这个挑选步骤再模拟“清掉通道后，未来几手能掉下多少棋、再造出什么道具”。

【设计解读】玩家可能看重打开通道后带来的后续机会，而程序当前这次攻击的评分未必区分这两个局面。是否真的少用步数，需要结合具体棋盘、后续补棋和操作验证，不能从同分随机本身推算胜率损失。

飞行途中会不会改目标：检查有效性，不是一直追逐全盘最高分

IsTargetValid会根据本次攻击类型询问当前目标是否仍有效，再检查失效标记。下面是已有目标时的主要分支；缺失目标的诊断路径省略。它说明检查被调用时怎样决定，不代表已经测出每架飞机每帧的调用频率。［P7］

例1：飞机正飞向箱子A，旁边刚出现一个评分更高的B。只要A仍有效、未被标记失效，这段检查就保留A；这里没有“再扫一遍全盘、发现B更高分就转弯”的步骤。

例2：A被其他爆炸清掉，目标接口变为无效，且还允许继续找目标，才进入重选路径。重选会处理旧的在途登记，再找新目标；未找到目标时另有自爆或取消移动等分支，不能承诺任何失效都一定成功改打别处。

还有强制重选入口。ForceTargetChangeOnce先检查是否已重定向过；使用OnlyIfZero策略时，还要求原目标评分为0。满足条件后设置失效／重定向标记、重新允许找目标，并取消强制格子目标状态。Default与OnlyIfZero不能混成一条“有更好目标就换”的规则。

ForceTargetChangeOnce():
    if redirectedOnce: return
    if strategy == OnlyIfZero and not TargetHasZeroScore():
        return
    redirectedOnce = true
    stoppedLookingForNewTargets = false
    invalidateTarget = true

这些入口与条件有原字节依据；全部触发通知来自哪些障碍、各飞行阶段何时停止重选，以及跨组合调用的完整频率，仍需继续追踪。代码支持的是有条件更新目标，不能写成“实时无限寻优”。

多架飞机怎样协同：先登记还没命中的攻击，再算还缺几下

普通箱子继承的基类规则可以直接写成减法。RemainingExplodeCount读取当前层数，再减去在途攻击容器的计数；选点成功后的登记会影响后续读取。它是在协调尚未发生的命中，不是把所有飞机分配给全盘的统一最优求解。［P4］

1层，已有1发在途1−1＝0跳过，避免再预订一次已够用的命中
3层，已有1发在途3−1＝2仍可选择同一箱子

这些例子限定普通箱子的基础计数路径，并假设登记已经生效、没有其他状态变化。特殊物体、覆盖层和范围组合的计数／登记各有实现，不能据此保证所有道具绝不重复或浪费。棋盘的Current／Next／Target登记负责移动，本文的incoming登记负责攻击，两者用途不同。

它会考虑任务，但不是所有障碍共用一条“任务最优”公式

任务确实进入部分评分链。例如，普通颜色棋的评分计算会读取对应目标还剩多少，并检查与窗帘、钻头等机制的关系；底部收集关还可能给清除路径的格子增加分数。由此可以解释为什么飞机有时会打普通棋，而没有直接撞向一个外观明显的障碍。［P5］

但各类物体的规则并不一致。箱子按类型给基础分，拳击手套在最后一次命中时提高分，颜色棋又有目标与机关条件。不能把这些分支概括成“永远攻击任务剩余最多的一类”，也不能把一张默认分值表当成所有状态下的最终排序。

玩家看到的收益还包括清覆盖、打开空间、帮助底部收集、激活机关和后续连锁。当前选点分数能表达其中一部分；它不是对所有未来收益的完整计算。

带火箭或TNT的飞机，会比较整条线或覆盖范围

飞机组合的攻击落到一格之后，还会向周围或整行整列生效。因此，它不能简单沿用普通飞机的单格分数来判断收益。客户端会按攻击触发类型，进入不同的目标选择入口。［P1、P6］

攻击形式比较什么与玩家体验的关系
普通飞机格子评分分组；在可用高分组内随机挑选同分目标可能换一个打，不保证优先处理只差一下的箱子
飞机＋竖火箭列评分、专用加减分，以及满足条件的直接完成目标检查落点自身价值低，其所在列也可能更值得打
飞机＋横火箭行评分及相关修正，与竖向路径分别处理要看整行收益，不能只数飞机落点处的障碍
飞机＋TNT以候选格为中心的范围评分、专用修正和完成目标检查落在两组障碍之间，可能比落在某个高分障碍正中覆盖更多有效目标
生成时的智能火箭方向生成格所在行与列的总分；较高的一边获选，同分才随机它只决定这个生成格的横竖方向；不是让已有火箭在全盘重新找位置

行列与范围的计算还包含果冻扩散、成组或多格障碍、机关和额外收集等专用处理。可以把它理解成“攻击覆盖的有效价值”，不能一律简化为范围内障碍数量相加；目前也不能为任意棋盘给出完整可靠的组合落点预测。

有些分支会先找“这次就能完成目标”的攻击

在已核对的竖向组合选择中，程序会逐列调用当前胜利计算对象的检查，把判断为可完成目标的列另存为候选。这个列表非空时，先从这些列里选；为空才进入普通的最高评分等后续选择。横向和范围攻击也有对应的胜利检查路径。［P6］

胜利计算会按这次攻击估计目标减量，再与剩余目标比较，并处理前置条件、特殊胜利目标等限制。它表达的是“在该分支建模的当前条件下，这次攻击能否收完目标”。它不是模拟剩余所有步数的自动解题器。

普通飞机入口没有统一先走上述行列组合的检查；不能因为存在胜利计算类，就宣称每一架普通飞机都保证飞到能立即通关的位置。特殊机关另有专用处理，完整适用范围仍需逐类核对。

这种选择是不是对玩家完成任务最优

现有证据不支持“保证最优”。可以确认的是：它按当前攻击类型和状态给候选评分，对一些收尾情况加分，用在途攻击计数减少无效重复，并在部分组合分支检查能否直接完成目标。

“最优”具体指什么目前能否成立
当前候选中，按程序这套规则优先取较高评分组普通单格选择的分组与遍历顺序有直接代码依据；失效候选、重定向和重选保留分支需要一并考虑
这次攻击能完成剩余目标时，优先抓住这个机会已在部分行列／范围组合分支找到明确处理；不能推广到每种道具、每种特殊目标
让整关所需步数最少，或让后续通关概率最高尚无此保证。在本页核对的选点入口中，没有看到展开后续多手操作和补棋结果、比较最终通关率的搜索

【设计解读】这种做法可以让道具更常命中有用位置，同时保留同分随机；代价是玩家心中“最该打的格子”，未必在评分中独占最高优先级。一层与三层箱子同分，就是可以具体解释的例子。要判断它比人工选点好多少，需要在同一批棋盘上比较后续操作与结果；目前没有这样的胜率或节省步数数据。

为什么有时感觉它“懂我”，有时又像选错了

【体验解读】这里把代码规则与玩家可能关注的结果对应起来；它不是玩家调研或原版胜率统计。

玩家期望代码怎样处理可能看到的结果
“这一下正好帮我收尾”拳击手套最后命中加分；部分组合先查当前能否完成目标在这些分支中，落点更贴近收尾需求
“别打已经够了的目标”在途登记扣减剩余命中，零以下跳过普通箱子场景可减少无效追加攻击；多层目标仍可能连续被打
“先打马上能清掉的那个箱子”1层和3层普通箱子基础分相同同分随机可能与玩家偏好相反
“局面变好了，快转去新目标”目标仍有效时保留，重选与强制更新受状态约束并非随时追着新最高分移动；飞行意图也更容易持续辨认
“帮我打开通道，方便后面几手”本页选点未展开未来多手及补棋结果的通关搜索当前评分高，不代表未来最省步数

要衡量“道具体验精准度”，还需要在同一批具体棋盘上记录：候选是否合法、是否命中玩家预期的关键目标、有效任务减量，以及是否发生无效追加攻击。现在能解释选择原因与局部收益，尚不能给出这类实测比例。

选中了目标，还要按它自己的受击规则结算

目标评分决定先考虑哪里，受击规则决定到达后发生什么。普通箱子命中后扣一层，剩余层数非零时受伤，到零才清除；彩箱还要检查攻击来源和颜色条件。道具能否选中、飞机能否伤害、是否阻挡，以及组合是否转向，是不同的条件，不能只看其中一个返回值。

智能火箭：方向与范围收益

分别计算横排和竖列的得分

智能方向选择会查看生成格所在的整行和整列，把每个格子对这次攻击贡献的分数分别加起来。物体类型、状态和攻击策略会影响分数，某些目标还会被排除。因此，棋子更多的一边不一定得分更高。

哪边分高，就朝哪边打

横排总分更高，选择横向火箭；竖列总分更高，选择竖向火箭。两边相等时，从0和1中随机取一个：1选竖向，0选横向。这个规则已在智能选择函数中确认；其他来源的火箭是否调用它，还需要逐项关联。

横分12、竖分8时会选横向

用一组示意数字来算：横排总分12、竖列总分8，火箭朝横向；改成8对12，就朝竖向；12对12才进入随机选择。12和8只用于说明比较方法，不是原版障碍的真实权重。下方可以修改数字查看结果。

方向选择怎样影响下一手

按目标分选择方向，有机会把攻击放到更有作用的一边。要复现这种效果，需要同时还原每类物体的贡献分和限制条件；仅把横竖方向做成各一半随机，无法还原已经确认的比较规则。
