道具寻优：目标选择与通关收益

先看三个结论

普通飞机选一个格；飞机＋火箭／TNT选一条线或一个范围；彩球先选一种颜色。这三种决策比较的对象不同，不能都理解成“找障碍最多的地方”。

决策实际比较核心规则
普通飞机打哪个障碍当前有效候选格的分数先看最高分组，再在组内抽选；剩余命中不足的跳过
组合飞机落在哪里整行、整列或落点周围的作用范围有当前一击可完成目标的候选时优先；否则按组合专用评分比较
彩球选择什么颜色可参与处理的颜色棋数量，或玩家指定颜色交换颜色棋时用该颜色；自动选色和道具组合时选有效数量最多的颜色

拆包事实：先解释实际决策顺序，再解释分值。分数是选择优先级，不是伤害值。

普通飞机：先选高分障碍，同分才随机

飞机先枚举棋盘上的格子，为每格取得本次攻击下的评分，然后把同分格子放进同一个列表。它按分数从高到低访问列表，不会从所有格子按分数比例抽奖。456,976分的箱子与676分的低分格同时有效时，低分格不会因为数量多就分走概率。［P1、P2］

  1. 确定攻击类型。普通飞机、彩球制造的飞机、飞机＋火箭、飞机＋TNT有不同的策略参数。障碍的评分方法能根据参数返回不同值。
  2. 筛格子。FillScores先检查普通有效格，以及是否存在阻挡飞机的覆盖物；随后还有成组物体等专用纳入条件。被过滤的格子不会参加后面的随机。
  3. 得到格子分数。先决定这一格该由哪个层的物体评分，再调用该物体的规则；原木／手套／钻头阻挡和底部收集关的清路价值还可能修正结果。详见下一节。
  4. 建立优先组。用“负评分”作有序字典的键，因此遍历顺序等于实际分数从高到低。只要高分组里还能选到有效目标，就不进入下一组。
  5. 组内抽选并验剩余命中。随机取下标；抽到出发格且组内至少两格时，改取相邻下标。然后检查当前目标是否还需要攻击：不足1次就剔除继续；等于1次，选中并从列表移除；大于1次，选中但保留它。
  6. 重定向与登记。TryRedirect允许具体物体把候选点转交给其他点；选定后通过AddIncomingExploder登记这次在途攻击，供后续飞机判断。

距离、屏幕位置、剩余层数都不是通用的组内排序键。剩余层数可能影响某个物体自己的评分，但不能据此推导“所有残血障碍优先”。

一格有多层：先确定评分对象，不把各层基础分直接相加

同一坐标可能同时有覆盖物、格内棋子／障碍、底层物体。ExplodeTargetMediator.CalculateScore按门控选择返回哪一个物体的分数。以下是普通飞机策略的主路径；“覆盖物”和“底层物体”使用StaticItemModel规则，与格内ItemModel是不同类型。［D1］

检查顺序条件取哪个分数
① 从最上方覆盖物往下找覆盖物仍有剩余命中，或它仍阻挡其他层立即返回这个覆盖物的评分，不再把本体和底层分数加上
② 格内障碍本体没有覆盖物接管，且格内物体的IsObstacle()为真返回这个障碍本体的评分
③ 可受击的底层物体格内没有障碍本体优先接管；按底层列表查找CanBeDamagedByPropeller为真的物体返回第一个满足条件的底层物体评分
④ 其他格内物体前面没有取得评分对象，格内还有普通棋／道具等返回其自身评分；无对象则返回0

因此，“某格下面还有一个任务目标”不会自动让这格获得两份基础分。物体自身的评分方法可以另外考虑覆盖机关、成组关系或额外效果；这属于该方法的专用计算。例如普通颜色棋的评分会询问冰块、鸟、穿梭器等辅助对象，不能把它简化为始终676分。

格子分数还有两类外部修正

  • 被原木／拳击手套／钻头阻挡：GetScore取得的分数若大于等于1，就统一返回4,569；0和负分保留。它是替换值，并非乘以1%。被飞机完全阻挡而提前过滤的格子，也不同于这种“保留但降分”的格子。［P5］
  • 底部收集关：满足攻击策略、物体与覆盖条件时，计算这次清除能释放的格子，再加入底部收集的专用评分。不是所有“看起来堵路”的格子都有通用加分，也没有在这里模拟后续多手掉落。［P1］

评分有帧数和策略缓存字段，但普通单格策略会进入重算分支，不能概括为“同一帧只算一次”。这样后续选点才有机会读到更新后的在途命中和物体状态。范围策略还有额外的缓存失效条件。［P5：0x2ACF290–0x2ACF2E4］

已执行原始评分路由代码的9组构造输入，包括覆盖物遮住高分本体、已预订完的覆盖物、障碍本体与底层并存、普通棋与底层并存等。对象的门控和分值是注入输入，用于验证选择哪个层，不代表已验证全部障碍的评分语义。

障碍怎样打分：基础优先级＋物体自己的状态规则

从分数表能归纳出什么规律

代码事实可以归纳为“基础类别档位＋部分物体的收尾规则＋格子修正”，再配合在途登记协调。这些步骤有条件分支，不能把它们直接写成所有障碍通用的加法公式。

  1. 基础档位以26倍拉开。1、26、676、17,576、456,976依次为26的0–4次方。普通飞机先访问最高有效分组；组合累计基础分时，25份低一档分值仍小于1份高一档分值，26份才相等。这个数值关系只适用于未叠加专用修正的基础档。［P1–P3］
  2. 剩余层数不构成统一排序。1层和3层普通箱子都为456,976；手套、碗柜则有最后一击加分。因此“残血优先”是特定物体的规则。［P3、D2］
  3. 多格物体的指定收尾分支按释放格数线性加分。原公式可等价改写为下面的形式；每多释放1格，分数增加152,325。只在剩余有效命中为1、攻击策略匹配且子类没有覆盖该逻辑时适用。［D2］

  1. 在途登记会提前改变收尾判断。当前还需3次命中、已有2发在途时，后续选点可按还缺1次处理；新的一击可能因此获得收尾分。这是对已安排攻击的协调，障碍此时尚未实际清除。［P4、D2］
  2. 指定阻挡条件会统一压低正分。4,569是固定替换值，约为456,976的1%；不能把这项规则推广为“所有物体都乘1%”。［P5］

［D — 设计解读］这些规则支持这样的理解：先用类别档位确定局部优先级，再对部分物体奖励能完成清除、释放空间的一击，并用在途登记减少过量预订。它们不保证任务收益、堵路价值或全局通关步数最优。依据：P1–P5、D2。

分数和障碍坐标有什么关系

表中箱子、手套、多格物体的自身评分，没有通用的距离、横坐标或纵坐标加权。把两个同状态箱子放到不同位置，只要评分对象、覆盖门控和额外修正相同，它们仍然同分。［P3、D2］

  • 所在位置的环境会影响最终分：覆盖物、特定阻挡和底部收集的清路条件可能不同。不能只凭坐标靠下，就断定有加分。［P1、P5、D1］
  • 同分抽选会受候选顺序影响：实际结果还依赖随机下标、候选列表和出发格避让。出发格是传入本次选点的起点格；其避让过程见下一节例子。这些会影响落点，不构成物体自身的坐标加分。［P2］
  • 范围组合与空间分布直接相关：飞机＋火箭比较整行／整列，飞机＋TNT比较落点周围；障碍是否集中、范围是否被棋盘边缘裁剪，会改变作用格与累计收益。组合还使用自己的物体评分和修正，详见07 组合飞机。［P6、D2］

“残血优先”和“任务优先”都要逐物体判断

普通箱子的基础评分没有读取任务剩余量，也没有用层数把箱子互相排序；普通颜色棋会读取目标剩余量和机关状态。多格物体用清除后释放的格数估算收尾收益。因而不能写成统一的“任务障碍→残血障碍→其他棋子”固定名单，更不能把层数−在途直接当分数：它同时用于判断是否还值得预订，并只在部分物体中触发加分。

把评分、筛选与随机连起来看

构造例子。假设候选格均有效，无额外底部收集修正；“被阻挡”一行只应用4,569出口修正。

候选状态最终用于比较的分数本轮处置
A 普通箱子剩1层，无在途456,976留在箱子所在组
B 普通箱子剩3层，无在途456,976与A同组，无额外“厚箱子”或“薄箱子”排序
C 拳击手套扣在途后还需1次命中609,301分组高于A、B
D 碗柜扣在途后还需1次命中913,951最高组，先选D

第一架：D独占最高有效分组，选D，并登记在途命中。下一架：在这些状态条件保持、D已无剩余命中的前提下跳过D，转而选C。再下一架：C也已预订完后，进入A／B／F组；F会被剔除，最终在A、B之间抽选。不会因为A只剩一层就固定选A。

这个例子也说明两件事：高分不等于一定能继续接收攻击，还要过剩余命中检查；同分不等于每次落点完全一致，还要知道随机数和候选列表顺序。

同分时的出发格避让

构造同分列表[出发格,A,B]，假设三格都有效且没有后续重定向。随机下标0、1、2最终分别对应A、A、B：出发格下标0被改成1。因此A为2/3，B为1/3。这是避让规则造成的局部偏差，不是A获得了更高评分。没有出发格避让等附加条件时，初始下标是组内均匀抽样。［P2］

如果一个箱子堵路，另一个在开阔处

只要两格的最终评分和候选条件相同，仍然同组抽选。底部收集关可以有专用清路加分；除此之外，没有证据支持“只要堵路就自动加分”，也没有在这个选点入口里展开后续几手造道具与补棋的搜索。

多架飞机：逐架预订，按剩余命中分流

普通箱子沿用ItemModel.RemainingExplodeCount：剩余命中＝当前层数−已登记在途攻击数。每架选中就登记；下一架使用更新后的剩余量。这里追踪的是计划中的攻击，不是已扣掉的生命值。［P4］

箱子状态后续读到的剩余命中后续飞机怎样处理
1层，1发在途0跳过，避免再订一发
3层，1发在途2仍可选；连续打同一厚箱子有效
3层，2发在途1还能订最后一发；选后移出候选列表

多格物体、覆盖物、范围攻击各有登记与剩余量实现，不能把普通箱子公式强套到所有障碍。整个过程也不是把全部飞机放在一起求最佳分配：它依赖选点次序与在途登记。这里的在途登记与棋子下落的Current／Next／Target占格是不同系统。

飞出去后：有效目标通常保持，失效才重新找

IsTargetValid检查当前目标对本次攻击是否仍有效。仍有效且未被标记失效时就保留，不会每帧追着全盘最新最高分转弯。目标被其他爆炸清掉、被标记失效且仍允许找新目标时，才重新选点并更新登记；找不到另走自爆或取消等分支。［P7］

ForceTargetChangeOnce每架只生效一次：Default策略可触发；OnlyIfZero策略要求原目标评分已为0。后续还受“已停止寻找新目标”等飞行阶段状态限制。具体哪些障碍发送重选通知，需要结合其调用方核对。

分数决定打哪里；受击规则决定消掉什么

选中456,976分的箱子，不会造成456,976点伤害。普通飞机到达目标格后，把这次攻击的数据交给目标格的受击流程，再由覆盖物、本体与底层的门控处理。是否扣层、是否收集、是否继续传递攻击，各物体自己决定。［D3、原门控矩阵］

  2. 判断能否受击：攻击来源、颜色、覆盖层阻挡、物体当前状态及去重规则，都可能影响结算。能被选中与能否伤害是不同判断。
  3. 按物体结算：普通箱子命中扣一层；还没到0则保留并播放受伤，到0才清除。彩箱等还检查来源与颜色，机关类不一定能直接扣层。
  4. 释放或更新计划：攻击结束或取消时更新在途登记；后续飞机据新状态选择。不能把“已预订最后一击”等同于“障碍已经消失”。

所以飞机在选点时奖励碗柜的最后一击，是估算它成功结算后能释放的空间；它不会因为这个奖励给碗柜增加伤害。完整的“可选中／可伤害／阻挡／重定向”条件，见页尾保留的障碍门控矩阵。

组合飞机：改变评估对象，也改变障碍分数

必须分开看两类组合：飞机＋火箭／TNT改变一次飞行携带的攻击范围；飞机＋飞机及彩球制造飞机则产生多次单格寻点。范围变大，不等于先选普通飞机最高分格，再无条件把范围搬过去。［P1、P6、D3］

组合选择单位怎样决定目标
飞机＋横火箭一整行及该行落点先查当前一击可完成目标的行；没有再比较行分与专用修正，随后确定行内落点
飞机＋竖火箭一整列及该列落点对应列分支；不是把每个落点当独立普通飞机来比较

7.1 飞机＋火箭：先看能否收完，再看整条线值多少

  1. 按组合类型取得格子分。传入横火箭或竖火箭策略，调用格子和障碍自己的评分；还要通过ShouldAddToTotalScore等专用条件。
  2. 累加行／列收益并做修正。不只是数格子：有成组物体、果冻扩散、底部收集、宝藏揭示、原木激活，以及其他机关和额外收集的专门处理。代码内部有负号存储，不能把内部负值直接解释为玩家损失。
  3. 检查这一击是否能满足胜利目标。WinCalculationData根据本次命中估算目标减量并检查剩余条件；能完成的行／列单独进入winningColumnsOrRows。
  4. 先从收尾列表选。该列表非空时优先使用它；否则返回普通评分比较。同分或多个候选的取舍还有随机／排除逻辑，不能声称永远选第一行或最近列。
  5. 再落到具体格子。已选行／列仍要确定可用落点；竖向路径还包括锁链底部收集、果冻扩散的优先格处理。落点本身不必是整盘单格最高分。

构造例子：候选行A只有1个有效普通箱子，行B有3个；假设其他格贡献为0、没有专用修正且都不能立即完成目标，B的基础合计为1,370,928，A为456,976，组合倾向B。若另一条行被收尾判断确认能完成全部剩余目标，它会进入更优先的收尾分支，即使普通合计较低。多层障碍“被命中一次”不等于“已清除”，胜利估算也不能只数覆盖了几个障碍。

7.2 飞机＋TNT：比较落点周围，而不只比较落点

ExplodeRadius(PropellerTnt)返回2。范围评分对每个中心计算周围作用格，加入专用物体与额外效果，再做当前胜利检查。候选筛选、零分中心、有效负分回退都有独立路径；因此下面只是结构说明，不是可替代全部物体逻辑的最终公式：［P6、D2］

范围价值(中心) = 作用格评分的有效累计
                + 成组／机关／额外收集／扩散／清路等专用修正
收尾判断(中心) = 本次范围命中能否满足剩余胜利条件

同一个碗柜，组合评分会改变：普通飞机收尾时为913,951；飞机＋TNT下，扣在途后还需2–10次命中时，碗柜自身返回456,976；只差1次或超过10次时返回228,488。它已经进入另一个评分分支，不能把普通飞机的913,951搬进每个范围格里重复相加。［D2；45组既有原字节执行回执］

同一多格障碍横跨多个作用格、机关额外生成收集物、范围内含彩球等情况，也各有专用校正。GetRandomItemFromAreaScores在带比较器时会先洗牌再排序；未带比较器时随机取列表项。不能把所有范围候选的最终选择统一描述为“最高分并列就等概率”。完整特殊分支仍有未恢复项。

7.3 多架单格飞机：数量增加，仍逐次找障碍

飞机＋飞机的NextExploder先调用普通策略，再设置组合的果冻扩散标记。彩球制造的飞机由普通策略生成另一种攻击来源，进入LightballPropeller分类；多格物体的收尾加分明确包含这个分类。两者都需要区分“生成了哪些飞机”和“每架去打哪个障碍”，逐架选点与预订不构成全盘最优分配。

没有飞机参与的火箭＋火箭、火箭＋TNT、TNT＋TNT，不能套用这里的飞机飞行选点算法；它们的作用区域由各自组合逻辑形成。彩球组合的选色在下一节单独说明。

彩球选色：玩家指定，或统计有效棋子数量

这条选色路径没有调用飞机的障碍评分，也没有逐颜色模拟“能打掉多少障碍”。DefaultLightballStrategy先看是否已传入一种颜色；没有时才调用FindMostCommonItem。彩球＋飞机／火箭／TNT的共同父类也调用这个数量选择器。［C1、C2］

8.1 “最多”统计的是什么棋子

FindMostCommonItem按列与当前棋盘Y范围枚举格子，先检查是否可以参与彩球处理，再对每种MatchType计数。它不是裸统计屏幕上所有同色图案。［C2、C3］

  1. 格子可处理：不能有“除锁链以外的触摸阻挡覆盖物”；必须有当前物体；格子不能处于IsReserved状态。锁链在这项覆盖物判断中被特别排除，不能说“所有覆盖物都会排除”。
  2. 物体是颜色棋：当前物体必须属于MatchItemModel，并且棋子自身也未被IsReserved预订。障碍、火箭、飞机、TNT和彩球不作为颜色棋计数。
  3. 累计每色有效数量：满足条件的每颗棋子给对应颜色加1；不乘任务权重，也不按邻近箱子、剩余层数或可生成的组合收益加权。
  4. 排除运行中的颜色：遍历计数表时，如果颜色已在SpecialItemCreator.RunningLightballTypes中，就不作为本次自动选择结果。
  5. 取最大值：只有count > bestCount才替换当前最佳颜色。所有颜色都不可用时，该选择器返回MatchType.None，后续如何结束由触发策略继续处理。
整理伪代码：原数量选择器的主要决策
counts = Dictionary<MatchType, int>()
for cell in 当前棋盘范围:
    if not IsReadyForLightball(cell): continue
    item = cell.CurrentItem
    if item is not MatchItemModel: continue
    if item.IsReserved(): continue
    counts[item.MatchType] += 1

best = None
bestCount = 0
for color in counts.Keys:
    if RunningLightballTypes.Contains(color): continue
    if counts[color] > bestCount:
        bestCount = counts[color]
        best = color
return best

8.2 同数时不重新抽一种颜色；随机打乱的是目标列表

颜色选择器里的最大值比较是严格大于。红、蓝都为8时，先枚举到哪种颜色，后遇到的同数颜色就不会替换它。该方法中没有同数选色的随机调用。不能据此承诺“红色永远优先”或“最左颜色永远优先”：还要知道计数字典在本次运行中的键枚举顺序。［C2：0x23985C0–0x23985C8］

选色之后，FindItemsByType建立所选颜色的可用目标列表，随后调用ShuffleList打乱列表，再发送射线。这个随机步骤改变处理顺序，不是把已选好的颜色再随机一次。普通和彩球组合的加入列表过程还会预订棋子。［C1、C4］

8.4 彩球组合：先选颜色，再执行该组合；两次决策不要混在一起

统计有效颜色棋→选有效数最多的颜色→射线处理／转换→生成的飞机各自评分选障碍
  • 彩球＋飞机：数量选择器决定“哪些颜色棋可能被转换”；生成的飞机再按LightballPropeller规则、障碍状态和在途计数决定飞往哪里。它没有先比较“红色9架最终能清多少障碍，蓝色8架又能清多少”再选择颜色。［C2、C5、D3］
  • 彩球＋火箭：同样先选数量最多的有效颜色；在当前列表收集路径中，替换火箭的朝向从参与组合的火箭朝向开始，随后横竖交替登记。这里的朝向分配没有逐位置调用页内的“智能火箭行列收益比较”。［C5：0x239B5B8、0x239B714］
  • 彩球＋TNT：也走同一个选色父类，再由TNT专用策略处理转换与爆炸。不能因为某色棋子旁的障碍更密，就推断选色会偏向它。［C5：0x239E718→0x239A530］

分析提炼：这些规则在优化什么

飞机优化当前攻击的局部优先级。物体类别、收尾释放空间、底部收集专用收益、在途攻击都会影响这一击；组合还检查能否就此完成胜利目标。没有在已核对入口中展开后续多手补棋、造道具和通关率搜索。不能称为全局最省步数求解器。依据：P1–P7、D1–D3。

普通飞机的不确定性主要发生在同分组内。箱子1层与3层同分时，玩家觉得应该优先的最后一层没有独占最高分；手套、碗柜有专用收尾分支则表现不同。高分目标无剩余有效命中时还会被跳过。依据：P2–P4、D2。

彩球自动选色优化的是可参与处理的颜色棋数量。它没有逐颜色比较障碍收益；这解释了为什么某色虽然更靠近障碍，也可能没有被选中。彩球＋飞机先选色，再由飞机选障碍，是串联的两次决策。依据：C1–C5。［设计解读］数量优先可提高一次触发的处理规模，但不保证最终障碍清除量最大。

分数与伤害分开，才能解释“选中了但没清掉”。厚箱子只扣一层是受击规则；被别的飞机预订完而跳过是选点协调；覆盖物接管是层级路由；飞行中失效才改点是目标稳定性。它们发生在不同步骤，不能用一个“飞机不智能”概括。依据：P2、P4、P7、D1、D3。
