普通飞机怎样选中一个目标

先按规则给每格评分，再从当前最高的可用分组里随机挑一个。高分组先于低分组；同一组内没有“最近”“层数最少”之类的二次排序。［P1、P2］

  1. 过滤格子。非普通格，以及被挡飞机的覆盖物盖住的格子，不进入候选。
  2. 评分。按上层覆盖物、格内物体、底层物体的顺序交给对应评分规则；物体种类、当前状态、攻击类型都会改变结果，底部收集关还会给清路的格子加分。
  3. 按分数分组。分数取负后存入有序字典，从小到大遍历，等于从高分组开始。
  4. 组内随机抽一格。用关卡随机数取下标；抽到飞机自己的出发格且组内不止一格时，改取相邻下标。
  5. 检查还缺几下。剩余命中≤0：移出本组继续抽；＝1：选它，同时移出本组；＞1：选它并留在组里。本组抽空才看下一组。
  6. 重定向并登记。目标可把攻击转交给另一个有效目标；选定后登记一发在途攻击，供后面的飞机扣减。
过滤格子→按当前状态评分→高分组优先→组内随机、检查剩余命中→重定向与登记攻击

评分档位：每档是上一档的26倍

客户端声明的层级倍数是26，五个基础档正好是26的0到4次方。所以只要两个目标差一档，低档目标凑满25个也追不上高档的1个。这些分数只用于选点排序，与玩家积分、金币和任务进度无关。［P3、P5］

物体也可以返回档位之外的修正分。已核对的几个：

目标状态评分效果
普通箱子，剩1层或剩3层456,976同分，层数不参与评分
拳击手套，还需1次命中609,301高于普通箱子，先进更高分组
拳击手套，还需多次命中456,976与普通箱子同分
正分目标被原木、拳击手套或钻头挡住4,569落到Medium与High之间，约为VeryHigh的1%
普通颜色棋按对应任务剩余量与窗帘、钻头等机关条件计算收集任务未完成时，飞机可能去打普通棋

评分按帧缓存：同一帧、同一攻击策略下重复查询同一格只算一次，阻挡修正在缓存值之上返回。上表是物体自身的评分分支；格子的最终分数还会叠加覆盖层、底层目标和底部收集加分，不一定等于物体基础分。

三个局面，分别会怎么选

按已确认代码构造的简化例子；只比较列出的有效候选，不加其他层和额外评分。

例1：左边箱子剩1层，右边箱子剩3层

两者都是456,976分，同在最高组时随机挑一个。左边一下就能打掉，并不会让它胜出——这就是玩家觉得飞机“打错了”的典型情况。

例2：一个普通箱子，对比只差一下的拳击手套

拳击手套609,301分，高于箱子的456,976，先被考虑。这是拳击手套专用的收尾加分，其他障碍没有这条规则。

例3：一个箱子堵着通道，另一个在开阔区域

两格分数和候选条件相同时，仍然组内随机。评分不模拟“清掉通道后会掉下多少棋、再造出什么道具”。

【设计解读】玩家看重的是打开通道带来的后续机会，而这一击的评分不区分这两个局面。

多架飞机协同：先扣掉已在路上的攻击

普通箱子的剩余命中＝当前层数－已登记的在途攻击数。每架飞机选中目标就登记一发，后面的飞机读到的是扣减后的值。这是按顺序逐架扣减，不是把所有飞机放在一起做全盘分配。［P4］

普通箱子当前状态后续读到的剩余命中处理
1层，已有1发在途1−1＝0跳过，不再预订
3层，已有1发在途3−1＝2仍可选，并留在候选组
3层，已有2发在途3−2＝1可选，选后移出候选组

所以两架飞机飞向同一个3层箱子是有效的连续攻击，不是浪费。多格物体、覆盖层和范围组合的计数与登记各有实现。这里的in-flight登记管攻击，棋盘的Current／Next／Target登记管移动，两者无关。

飞行中改不改目标：有效就不改

IsTargetValid按本次攻击类型询问当前目标是否仍有效。仍有效且没有被标记失效，就保留原目标，不会因为旁边出现更高分的目标而转弯。［P7］

  • 目标被别的爆炸清掉：目标变为无效，若还允许继续找，就撤销旧的在途登记并重新选点；找不到时走自爆或取消移动等分支。
  • 强制重选：ForceTargetChangeOnce每架飞机只生效一次。Default策略直接触发；OnlyIfZero策略要求原目标评分已降到0。

飞机＋火箭／TNT：先找能直接收完目标的，再比整线或范围

组合飞机落地后还会清整行、整列或一片范围，所以按攻击覆盖的总价值选落点，不用单格分数。客户端按触发类型进入不同的选点入口。［P1、P6］

攻击形式比较什么玩家看到的
普通飞机单格评分分组，高分组内随机同分目标随机，不保证先打只差一下的箱子
飞机＋竖火箭先找能直接完成目标的列；没有再比列总分和专用修正落点本身价值低，但它所在的列更值
飞机＋横火箭同上，按行看整行收益，不只看落点
飞机＋TNT以候选格为中心的范围评分、专用修正和完成目标检查可能落在两组障碍之间，覆盖更多有效目标

“能直接完成目标”由胜利计算对象判断：按这次攻击估算目标减量，与剩余目标比较，并处理前置条件和特殊胜利目标。竖向组合逐列调用它，把能完成的列另存；这个列表非空就从中选，空了才回到普通评分。横向和范围组合有对应路径。它只看这一击，不模拟剩余步数。

行列与范围的评分还专门处理果冻扩散、成组或多格障碍、机关和额外收集，不等于范围内障碍数相加。普通单架飞机没有这道“能否收完”的检查。

智能火箭：只决定横竖方向

智能火箭只决定横向还是竖向，不挪生成位置。全库直接调用它的只有三处：开局火箭道具放到棋盘上时（BoosterManager.CreateSpecialItem）、Cloche放出火箭时、SlotMachine抛出火箭时。三消四连生成的火箭不走这里，方向由形状决定：竖排四连出横火箭，横排四连出竖火箭，见棋盘状态机。［S1］

规则：分别累加生成格所在整行、整列每格对这次攻击的评分，哪边总分高就朝哪边打；两边相等时用关卡随机数在0和1之间取一个，1选竖向，0选横向。评分沿用上面的档位与修正，所以棋子多的一边不一定分高；一个VeryHigh目标就能压过一整列低档目标。

伪代码：智能火箭方向6行
horizontal = 生成格所在行各格.GetScore(横向火箭策略)之和
vertical   = 生成格所在列各格.GetScore(纵向火箭策略)之和

if horizontal > vertical: return 30 // 横向火箭
if vertical > horizontal: return 20 // 纵向火箭
return levelRandom.Next(0, 2) == 1 ? 20 : 30

横向从该行x=0的格子沿右邻居累加，策略参数2；纵向从该列棋盘起始行（BoardStartY）沿上邻居累加，策略参数1。两种策略分别取分，同一格对横、竖贡献的分数可以不同。

例子：横向各格贡献“0、4、0、3、0”，总分7；纵向“2、0、0、1、2”，总分5，返回横向火箭30。纵向改成8返回20；两边都是7进入随机。数字是示意值。

是不是最优：只看当前这一击

选点是对当前这一击的贪心评分：按攻击类型和状态打分，对少数收尾情况加分，用在途计数避免打重，组合飞机先找能直接收完目标的落点。选点入口里没有展开后续多手、补棋和通关率的搜索。

玩家期望代码怎样处理结果
“这一下正好帮我收尾”拳击手套最后一击加分；组合飞机先查能否收完目标✅ 这些分支会抓住收尾机会
“别打已经够了的目标”在途登记扣减剩余命中，≤0跳过✅ 普通箱子不会被多订；多层目标仍会被连续打
“先打马上能清掉的箱子”1层和3层普通箱子同分❌ 同分随机，可能打另一个
“局面变了，快换目标”目标仍有效就保留；强制重选每架只一次❌ 不追新的最高分；但飞行意图稳定、好辨认
“帮我打开通道，方便后面几手”不模拟后续掉落与连锁❌ 当前分高不代表后面省步数

【设计解读】26倍分档加同分随机，让道具稳定地命中“重要类别”的目标，同时保留一点不可预测；代价是玩家心中最该打的那一格，未必独占最高分。比人工选点省多少步，需要同一批棋盘的对照数据，包里没有。飞行曲线是另一套表现逻辑，与选点无关。

选中之后：按目标自己的受击规则结算

评分决定先考虑哪里，受击规则决定到达后发生什么。普通箱子命中扣一层，未到0播受伤，到0清除；彩箱还要检查攻击来源和颜色。“道具能否选中”“能否伤害”“是否阻挡”“是否转向”是四个独立条件，要分别看。

页尾保留30类目标×19类条件的门控矩阵：157项是动态逻辑，33项委派给其他实现；矩阵中的“未声明”指该类分支里没有声明这个方法。
