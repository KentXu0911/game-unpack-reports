数据从哪来：后台下发一张“ID→组值”表

后台响应带回key／value→客户端替换实验表并存本地→判断函数按组值返回true／false或组值→各系统决定开哪个分支

三条后台命令会带回实验表并调用UpdateAbTestData：定期Ping、上传进度UpdateUserProgress、主动申请分组AssignCampaignAB。账号迁移或切换到后台决定的账号时，先清空再更新。更新后，客户端通知活动锁定、局内广告、Xsolla支付三个模块重新读取，并刷新推送标签。［A1］

主动申请分组只有一处：国王工坊桌游（ID 230）由KingWorkshopManager发出申请。其余实验都是后台自己分好组，随普通响应下发。

每个主题通常有两个ID：…NewUser和…OldUser。判断函数一般“任一ID命中就成立”；取组值的函数先读新用户ID，为0再读老用户ID。按命名后缀归并后，107个ID是55个主题，其中包括隐私、赛事、通知等非商业化实验，也不代表当期都在运行。

判定规则长什么样：组值决定开哪个分支

组值是一个小整数。全部判断函数里，组0和组1不开任何分支，分支从组2开始；唯一例外是安卓上的进度保存提醒，两个ID都为0时走替代版本。同一主题的不同组值，常常对应不同的改动组合，而不只是“开／关”。

规则的取得方法：直接执行原ARM64字节，把读实验表的函数替换成“返回指定组值”，对每个ID依次试组值0–10，记录返回结果；判断函数内部调用的其他判断函数照常执行，函数外的调用分别按返回0和1各跑一遍。97个函数全部跑通，没有执行错误。［A2］

原字节整理：关末金币缩减与取组值9行
IsLevelEndRewardReductionAbEnabled():
    if this[128] == 2 or this[129] == 2: return true
    if this[128] == 4 or this[129] == 4: return true
    return this[128] == 5 or this[129] == 5
