分析层

六套分组方式的对照、远征档位表和购买后变化表在页尾展开，下面每条结论都可点开对应表核对：

依据：分层输入、作用范围与变化方式 依据：远征1–5档默认能量内容 依据：购买后状态与下次展示反馈
分层值都落在同一个用户结构里，但彼此独立。同一个 BasicUserData 同时带 UserOfferSegment、IsPaidUser、GetHighestBoughtBundle、GetHighestBoughtSinglePackage 四个不同标签，另有聊天与社交封禁标记。依据：分层与档位在客户端结构里的落点标签之间没有换算关系，不能合成一个总价值分。
阶梯礼包按版本与入口优先级取配置。LadderOfferConfig 声明了 version、theme、steps 以及首页、商店、收藏三个入口的优先级字段。依据：分层与档位在客户端结构里的落点所以同一份阶梯配置能按入口分开展示，取哪一份由版本号与档位共同决定。
付费身份只影响两处商品。Ego Offer 与极难关礼包各有一组付费／未付费商品（egooffer.7 与 egooffer.1、extremelyhardleveloffer.3 与 .1）。依据：按付费身份分叉的商品这是客户端可见的、最直接的“按身份换商品”。
远征档位自带升降规则。远征的档位对应不同能量量的商品标识（日用礼包、通行证、单品三组前缀），换期时按买没买、看没看来升降档。依据：远征活动的能量类商品（按档位与用途分前缀）依据：远征1–5档默认能量内容买过升一档、封顶 5；未买且看过且挂起且档位不低于 3 时降一档；没有档位时用服务端给的值。依据：远征1–5档默认能量内容
购买不只发奖，还会留下状态。常规礼包会更新付费身份与对应类别的历史最高档，通行证只解锁当期付费轨而不更新常规最高档，这些状态又会被货架与礼包起步步骤读取。依据：购买后状态与下次展示反馈

远征日礼包：在换期时才计算下一档

Short Expedition日礼包使用1–5档。算法分别读取当前档位、上期买过low或high、是否展示过报价，以及之前的待降标记。原方法不是简单统计“连续几天没买”。

// 按GetUpdatedSegment与ComputeNextSegmentDecreasePending整理。
// bought、seen、oldPending均指这次换期检查的对应状态。
if noCurrentSegment:
    nextSegment = min(serverSegment, 5)
else if boughtLow || boughtHigh:
    nextSegment = min(currentSegment + 1, 5)
else if seen && oldPending && currentSegment >= 3:
    nextSegment = currentSegment - 1
else:
    nextSegment = currentSegment

nextPending = false if bought else (seen XOR oldPending)

例如，当前3档、上期买过礼包，下期升到4档；当前3档、看过但没买、原待降标记为false，这次不降档，但会把标记设为true；之后换期检查时仍然看过未买且旧标记为true，才会降到2档。无展示时虽然档位不降，pending计算仍会保留旧值，不能把它概括成“没看就清零”。

原方法：GetUpdatedSegment · 0x37C3704；ComputeNextSegmentDecreasePending · 0x37C37FC。下方默认能量表说明每档的奖励规模；当前配置覆盖与地区售价仍需外部输入。

分组实验的具体组值见A/B测试；礼包怎样竞争展示见触发与展示。分层标签本身没有证据支持“会改关卡seed或棋子概率”。

货架会记住玩家曾经接受过的档位

Purchase validated -> BasicUserData.UpdateUserData(PurchaseProduct) -> PaidUser = true -> update highest bundle tier OR highest single-package tier (Pass products do not enter these two maxima) -> GetShortList / GetLongList / new ShopSection reads both maxima -> OfferManager.CalculateFirstStepForOldVersions may skip lower steps

这说明历史购买档不只是埋点。它真的进入商店筛选与特殊礼包起步档的调用链。但 numberId 只是客户端档位，不能直接当成当地货币实价。

No Ads 的特别分支：历史已购商品所含金币量达到 >= 5000 时，客户端才尝试把单独去广告商品替换为去广告礼包版。该门槛由ARM64条件分支确认。

人工／实机能做到什么，解包增加什么

人工／实机：部分能。用不同购买历史的账号，跨期记录商品和奖励，可观察分层差异、测试升降档假设；但只覆盖已测试账号，难以分清背后是哪套标签。

解包增量：能拆出付费身份、历史最高购买档、活动内档位等独立标签，找到它们影响商品的位置，并读到远征日礼包的本地升降档规则。Dynamic／Revenue的后台分组公式和账号当期层级仍需外部证据。
